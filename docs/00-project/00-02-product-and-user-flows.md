# 00-02 产品范围与用户流程

## 1. 核心角色

### 用户

使用时间线、审核工作台、Agent 对话、卡片编辑器、设置中心和实时语音输入。

### Workspace Agent

应用内置 Agent。读取 Agent Pack 和当前能力策略，代表用户调用应用全部已启用能力。

### 外部 Agent

通过 A2A 发起高层任务，或通过 MCP 调用较原子的能力和读取资源。

### 编程 Agent

读取 `AGENTS.md`、OpenAPI、Schema、模块文档、测试与执行记录，用于实现、审阅和调试。

## 2. 主流程 A：采集与时间线

1. 用户选择“立即采集”，或调度器按时间触发。
2. 选择来源、主题和时间范围。
3. Collection Graph 并行抓取来源。
4. 系统标准化 URL、标题、时间和正文。
5. 确定性去重后，LLM 完成摘要、标签和价值判断。
6. 形成采集批次与日期时间线。
7. 用户或 Agent 打开待审核列表。

### 最小来源

- 可配置 RSS/Atom；
- GitHub Releases；
- 人工配置的官方博客页面；
- 一个通用搜索 Provider。

## 3. 主流程 B：批量审核

用户可以：

- 保留；
- 拒绝；
- 延后；
- 标记重点；
- 修改标题、摘要、标签；
- 合并重复事件；
- 选择主要证据来源；
- 批量确认是否进入卡片草稿。

Agent 可以执行同样动作，但是否需要确认由能力策略决定。

## 4. 主流程 C：卡片生成

1. 用户选择已批准的信息。
2. 系统显示将生成的数量与模板。
3. 用户确认。
4. Poster Graph 生成结构化文案草稿。
5. 用户在编辑器中修改文字、图片和版式选项。
6. 用户确认渲染。
7. Playwright 将 HTML/CSS 模板导出 PNG。

第一版只做一套稳定模板，不引入图片生成模型。

## 5. 主流程 D：Agent 对话

示例：

```text
收集过去 24 小时内 Agent 和 AI Coding 相关的重要信息。
把非官方来源单独标记，不要删除。
评分高于 80 的先保留，但不要生成卡片。
```

Agent 应当：

- 查看当前启用能力；
- 解析任务；
- 调用 Collection/Timeline/Review Capability；
- 对需要确认的动作返回审批请求；
- 将执行结果以结构化 UI 展示。

## 6. 主流程 E：实时语音输入

1. 用户在任意支持的文本输入区点击麦克风。
2. 浏览器请求麦克风权限。
3. 前端建立转写会话和 WebSocket。
4. 麦克风音频持续发送到转写服务。
5. UI 显示 partial transcript。
6. 服务返回 final segment 后，前端追加到输入框。
7. 用户可暂停、继续、修改或清空文字。
8. 文字只有在用户点击发送/保存后才进入 Agent 或业务流程。

实时语音转文字只是输入方式，不直接自动执行 Agent 操作。

## 7. 日期时间线

逻辑分片而非数据库物理分区：

- 今天；
- 昨天；
- 本周；
- 上周；
- 月份；
- 自定义范围。

统一保存 UTC，前端按工作区时区聚合。

## 8. 第一版页面

- `/timeline`：时间线和过滤器；
- `/review`：批量审核；
- `/agent`：Workspace Agent；
- `/cards`：卡片草稿列表；
- `/cards/[id]`：卡片编辑；
- `/settings/sources`：来源配置；
- `/settings/agent`：Agent Pack 与能力开关；
- `/runs/[id]`：执行详情与调试。
